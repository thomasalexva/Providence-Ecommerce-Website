Bootstrap

server.js

This is the main server bootstrap entry script. It configures and launches the Express HTTP server process.

startServer() Async

Purpose: Boots up the backend services sequentially.

const startServer = async () => {\n await connectDB();\n await seedDatabase();\n app.listen(PORT, () => console.log('Server running...'));\n};
  • Step 1: Runs connectDB() asynchronously to establish connection constraints.
  • Step 2: Invokes seedDatabase() to verify that template accounts and products are loaded.
  • Step 3: Starts the server listener on the resolved system PORT (defaults to 5000).
Config

config/db.js

Initializes the connection parameters to MongoDB, defining fallback variables in case the local database is offline.

connectDB() Async

Purpose: Bootstraps Mongoose or enables the JSON file-based database fallback flag.

const connectDB = async () => {\n const mongoURI = process.env.MONGODB_URI || 'mongodb://127.0.0.1:27017/providence_ecommerce';\n try {\n await mongoose.connect(mongoURI, { serverSelectionTimeoutMS: 2000 });\n global.useMockDb = false;\n } catch (err) {\n global.useMockDb = true;\n }\n};
  • Step 1: Resolves environment MONGODB_URI or falls back to local port 27017 connection.
  • Step 2: Attempts mongoose.connect() using a short 2-second timeout.
  • Step 3: If connection fails, it catches the error, marks global.useMockDb = true, and falls back to a JSON-based local database.
Database Seeding

config/seeder.js

Pre-populates the database with default administrative, customer, and listing data if it is empty.

seedDatabase() Async

Purpose: Checks collection records and writes default documents.

  • Step 1: Evaluates User count via User.countDocuments({}).
  • Step 2: If count is 0, generates a bcrypt salt and hashes password strings for Admin (admin@techstore.com / admin123) and Client (alen@techstore.com / client123).
  • Step 3: Inserts user documents into the collection.
  • Step 4: Seeds 6 initial electronic and lifestyle product listings, complete with prices and mock image URLs.
Database Proxy

models/modelFactory.js

Implements a proxy pattern, routing database requests dynamically depending on connection state.

ModelProxy Class Proxy Gateway

Constructor Parameters: (name, schemaDefinition, collectionName)

get model() {\n if (global.useMockDb) {\n if (!this._mockModel) this._mockModel = new MockModel(this.collectionName, this.schemaDefinition);\n return this._mockModel;\n } else {\n if (!this._mongooseModel) {\n const schema = new mongoose.Schema(this.schemaDefinition, { timestamps: true });\n this._mongooseModel = mongoose.model(this.name, schema);\n }\n return this._mongooseModel;\n }\n}
  • Role: When controllers query database operations, ModelProxy checks the global.useMockDb flag.
  • Routing: If true, redirects database queries to a MockModel instance. If false, creates a standard Mongoose Schema and returns a MongoDB Mongoose Model.
  • Proxy Methods: Binds common methods (find, findOne, findById, create, etc.) directly to the active underlying model adapter.
File Database

models/dbFallback.js

Simulates MongoDB CRUD queries by writing and reading data structures directly to a local JSON file (`data/db.json`).

MockModel Methods File system adapters

  • readData() / writeData(): Native Node.js fs.readFileSync and fs.writeFileSync handlers that parse and save database collections to disk.
  • find(query): Reads data collections and performs array filtering, supporting regular expressions (regex) for search and keyword filters.
  • findById(id): Finds records matching the target ID and wraps the return object with an asynchronous save() function so controllers can modify fields dynamically.
  • create(docData): Generates random alphanumeric ID values, sets date timestamps, appends the document, and serializes it back to db.json.
  • findByIdAndUpdate(id, updateData): Finds target indexes and applies updates (supporting $set structures).
  • findByIdAndDelete(id): Splices documents from the memory array and writes updates back to disk.
Data Schemas

models/User.js, Product.js, Order.js

These files outline the database models. Mongoose and the fallback JSON engine share these exact structures to ensure uniform properties:

User Schema Fields

username (String), email (String), password (String), role (enum: ['client', 'admin']), isSuspended (Boolean), contactDetails (String), profilePicture (String), address (String).

Product Schema Fields

title (String), description (String), price (Number), category (String), location (String), sellerId (String), sellerName (String), images (Array of Strings).

Order Schema Fields

buyerId (String), buyerName (String), totalAmount (Number), shippingAddress (String), paymentStatus (enum: ['Pending', 'Paid', 'Failed']), status (enum: ['Processing', 'Shipped', 'Delivered']), items (Array of product specifications: productId, title, price, quantity, image).

Middleware

middleware/auth.js

Intercepts HTTP requests to enforce access control permissions before they reach controller paths.

protect(req, res, next) JWT Validation

Purpose: Validates user tokens and attaches user state to the request.

  • Step 1: Checks if req.headers.authorization exists and starts with Bearer.
  • Step 2: Extracts and decodes the JWT using jwt.verify(token, JWT_SECRET).
  • Step 3: Fetches user metadata from the database using the decoded ID.
  • Step 4: Checks if user.isSuspended is true. If suspended, rejects the request immediately with a 403 Forbidden response.
  • Step 5: Attaches the user profile to req.user and invokes next() to continue request handling.

adminOnly(req, res, next) Role Authorization

Purpose: Restricts access to administrative endpoints.

  • Step 1: Checks if req.user is populated and has the admin role.
  • Step 2: If verified, calls next(). Otherwise, returns a 403 Forbidden response.
Controllers

controllers/authController.js

Coordinates login, registration, and user profile management.

registerUser(req, res) Account Creation

  • Checks if username, email, and password exist. Checks email uniqueness.
  • Hashes password with bcrypt salt cycles, creates user, and returns signed JWT token.

loginUser(req, res) Authentication

  • Looks up user by email. Compares password hashes using bcrypt.compare.
  • Asserts the account is not suspended. Returns signed JWT credentials.

updateUserProfile(req, res) Profile update

  • Locates user by ID. Updates credentials. Re-hashes password if changed, then saves.
Controllers

controllers/productController.js

Manages listing queries, item creation, and deletion checks.

getProducts(req, res) Search & Filtering

  • Gathers query parameters (keyword, category, location, sellerId).
  • Constructs a dynamic query object using case-insensitive regex for text search.
  • Fetches and returns matching documents.

createProduct(req, res) Add Listing

  • Validates required fields. Asserts that price is a positive number.
  • Binds the product to the active seller ID (from `req.user.id`).

deleteProduct(req, res) Remove Listing

  • Finds the listing by ID. Verifies that the requester is the listing owner or an administrator.
  • If validated, deletes the listing.
Controllers

controllers/orderController.js

Handles checkouts and mock transaction processing.

createOrder(req, res) Checkout & Payment Processing

  • Validates that items exist and shipping address is provided.
  • Validates credit card parameters (card number, expiry, CVV format).
  • Mock Gateway Simulation: If the credit card number ends in 0000, it simulates a declined payment, returning a 402 Payment Required response. Otherwise, sets status to Paid and saves the order.

getUserOrders(req, res) Order History

  • Retrieves all orders matching the buyer's ID, sorted by creation date.
Controllers

controllers/adminController.js

Orchestrates administrative controls and statistics operations.

getDashboardStats(req, res) Metrics Aggregator

  • Counts users, products, and orders. Sums the total revenue of paid transactions.

toggleUserSuspension(req, res) Moderation Control

  • Locates the target user. Prevents suspending administrators.
  • Toggles the user's isSuspended boolean flag, immediately blocking them from accessing the app.
Routing

routes/authRoutes.js, productRoutes.js, orderRoutes.js, adminRoutes.js

Maps API endpoints to their respective controller methods, applying protection middlewares where required:

Authentication Routes (`/api/auth`)

BULLET:POST /register - Maps to registerUser (Public)

BULLET:POST /login - Maps to loginUser (Public)

BULLET:GET /profile - Maps to getUserProfile (Protected by `protect` middleware)

BULLET:PUT /profile - Maps to updateUserProfile (Protected by `protect` middleware)

Product Routes (`/api/products`)

BULLET:GET / - Maps to getProducts (Public)

BULLET:POST / - Maps to createProduct (Protected by `protect` middleware)

BULLET:GET /:id - Maps to getProductById (Public)

BULLET:DELETE /:id - Maps to deleteProduct (Protected by `protect` middleware)

Order Routes (`/api/orders`)

BULLET:POST / - Maps to createOrder (Protected by `protect` middleware)

BULLET:GET /myorders - Maps to getUserOrders (Protected by `protect` middleware)

Admin Routes (`/api/admin`)

BULLET:GET /stats - Maps to getDashboardStats (Protected by `protect` and `adminOnly` middlewares)

BULLET:GET /users - Maps to getAllUsers (Protected by `protect` and `adminOnly` middlewares)

BULLET:PUT /users/:id/suspend - Maps to toggleUserSuspension (Protected by `protect` and `adminOnly` middlewares)
